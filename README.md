# ColorDetector + M5Stack Cardputer

## Purpose

ColorDetector is a Windows desktop application paired with custom firmware for
an M5Stack Cardputer (ESP32-S3 / M5Stamp S3A). The application watches a
circular area at the center of the primary display. While activated, it checks
the pixels against colors loaded from `colors.txt`. A match sends `CLICK` over
a persistent USB serial connection. The Cardputer then produces the real USB
HID mouse click.

Mouse clicks and snap-back movement are generated by the external Cardputer.
The application does not use `SendInput`, `mouse_event`, `PostMessage`, or
another Windows input-injection API.

## End-to-End Flow

1. `Program.cs` loads persisted settings and opens the control GUI, hidden
   detector form, and optional circle overlay.
2. The detector is activated with Left Ctrl in either HOLD or TOGGLE mode.
3. `ScreenCapture.cs` performs one native GDI `BitBlt` capture of the square
   surrounding the watched circle.
4. Only pixels geometrically inside the circle are scanned.
5. `ColorStorage.cs` checks each pixel against a precomputed 24-bit lookup
   table generated from `colors.txt`.
6. A match records the current cursor position and applies the configured
   reaction delay.
7. `CardputerClient.cs` sends `CLICK\n` over the already-open serial port.
8. Firmware sends a USB HID left-button down report, waits 5 ms, and sends the
   button-up report.
9. After the configured snap-back delay, the app reads the new cursor position,
   creates a smooth path to the recorded point, and sends `MOVE x y` commands.
10. Closed-loop position feedback keeps correcting until the saved coordinate
    is reached or a five-second safety timeout occurs.

There is a one-second click cooldown in `OverlayForm.cs`.

## Activation Modes

- **HOLD:** detection runs only while physical Left Ctrl is held.
- **TOGGLE:** each physical Left Ctrl press toggles detection on or off.
- Changing modes resets toggle state to off.
- The activation mode is saved.

## GUI Controls

- Reaction delay: `0-500 ms`.
- Detection rate: `30-1000 FPS`.
- Watched circle diameter: `1-250 px`.
- Circle visibility: visible or hidden; hiding does not disable scanning.
- Snap-back delay: `0.5 ms-1 second` in 0.5 ms units.
- Return-time multiplier: `0.25x-4.00x`.
- Activation mode: HOLD or TOGGLE.
- Watched-color preview and activity console.

The GUI uses a near-black dashboard style with charcoal cards, rounded badges,
Mica where supported, and cyan/purple/pink/orange gradient accents.

## Color Matching

`colors.txt` contains one `#RRGGBB` value per line and is copied to the output
directory during build.

The current default similarity tolerance in `ColorStorage.cs` is **5%** of the
full 0-255 range for each RGB channel. That equals +/-13 channel values. Exact
matches are included. The default lookup table consumes about 16 MB and makes
each default-tolerance test constant time.

`Contains(r, g, b, tolerancePercent)` also accepts another percentage, but a
non-default percentage uses a slower scan of source colors.

## Serial Protocol

Connection settings:

```text
Baud: 115200
Line ending: \n
USB vendor: VID_303A
```

Commands and responses:

```text
CLICK
OK CLICK

MOVE <x> <y>
OK MOVE
```

Errors return `ERR HID`, `ERR MOVE`, or `ERR UNKNOWN`.

The firmware splits movement larger than the signed HID report range into
multiple reports. The desktop app serializes access to the persistent port.

## Firmware Build

The project has a portable Arduino data directory:

```text
diagnostics\arduino-m5-2.1.4\arduino-cli-portable.yaml
```

Required board package: `esp32:esp32 3.3.10`.

Use this FQBN:

```text
esp32:esp32:m5stack_cardputer:USBMode=default,CDCOnBoot=cdc,UploadMode=cdc,FlashSize=8M,PartitionScheme=default_8MB
```

Firmware defines `USB_PID 0x4048`. The portable ESP32 core contains an important
input-only TinyUSB HID descriptor patch in:

```text
diagnostics\arduino-m5-2.1.4\data\packages\esp32\hardware\esp32\3.3.10\libraries\USB\src\USBHID.cpp
```

Do not replace that portable core or compile with CDC disabled: doing so can
produce HID-only `PID_1001`, removing the serial interface.

## Flashing

Normal automatic flashing may work while the serial interface is available.
For manual bootloader mode:

1. Hold `G0`.
2. Tap `RST`.
3. Release `G0`.
4. Find the bootloader port, commonly `COM3`.
5. Upload the compiled firmware.
6. If it remains in bootloader mode, tap `RST` once without holding `G0`.

After startup, verify Windows shows all three:

- USB Composite Device `VID_303A&PID_4048`
- USB Serial Device
- HID-compliant mouse

## Windows Mouse Stack Requirement

The Cardputer previously enumerated correctly but Windows did not deliver its
clicks because global mouse upper filters intercepted the HID device. The
working mouse class filter list is only:

```text
mouclass
```

The removed filters were `mouse` (Interception) and `ccmouse` (Custom Curve).
The backup created during diagnosis is:

```text
diagnostics\mouse-class-backup.reg
```

Do not reinstall or restore those filters without retesting Cardputer HID input.

## Performance Notes

- Timer resolution is set to 1 ms while the app runs.
- The detection thread uses above-normal priority.
- The app skips screen capture entirely while inactive.
- A larger watched circle increases the number of scanned pixels.
- The 5 ms click pulse is the lowest duration that passed the hardware test.
- A requested 0.5-2 ms snap-back delay is best effort; serial handling and the
  reliable 5 ms click pulse create a higher practical end-to-end minimum.
- Windows pointer acceleration means reverse relative movement is not exact.
  Snap-back therefore reads the resulting cursor coordinate and corrects it.

## Known Risks and Limitations

- The watched area is centered on the primary monitor.
- The displayed watched color is stabilized and may lag raw detection.
- Snap-back movement remains relative HID movement, so exact restoration may
  take multiple feedback corrections.
- A new snap-back cancels an older return path.
- The app reads cursor coordinates with `GetCursorPos`; it does not generate
  movement through Windows APIs.
- The project currently targets preview `.NET 10`, which produces an SDK
  support warning.

3. Launch the app and confirm `Cardputer connected.` in Activity.
4. Verify `CLICK` produces a real raw HID down/up pair.
5. Verify `MOVE 20 10` returns `OK MOVE` and moves the cursor.
6. Confirm HOLD and TOGGLE activation modes.
7. Confirm circle visibility does not change the detection area.
8. Confirm settings survive restart.
9. Confirm snap-back returns to the recorded cursor coordinate.

## Engineering Rules for Future Work

- Preserve external hardware generation for clicks and movement.
- Do not substitute Windows input-injection APIs.
- Keep the serial port open instead of reconnecting per command.
- Preserve `PID_4048`, TinyUSB CDC, and the input-only HID core patch.
- Build and test both desktop and firmware changes when protocol behavior changes.
- Avoid repeated manual bootloader requests: compile first and request one boot
  cycle only when automatic reset is impossible.
